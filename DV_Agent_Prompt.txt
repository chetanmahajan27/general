# Build a Professional Cross-Platform Data Validation Framework

## 1. Objective

Build a **professional-grade, enterprise-ready Data Validation Framework** as a desktop application that runs on both:

* Windows 10/11
* macOS

The application must allow users to configure, execute, monitor, and analyze data validation/comparison jobs between two databases.

The framework must support:

### Source/Target Database Types

1. MySQL
2. PostgreSQL
3. Oracle
4. Snowflake

A validation can compare any supported database against any other supported database.

Examples:

* MySQL → PostgreSQL
* Oracle → Snowflake

* Snowflake → Snowflake
* Oracle → Oracle

The application must be designed so that additional database types can be added later without redesigning the framework.

# 2. Critical Design Principles

The application must follow these principles:

### Configuration-driven

**No business logic, database connection details, validation rules, mappings, thresholds, SQL queries, or execution parameters should be hardcoded.**

Everything possible must be externalized into:

* YAML configuration files
* JSON configuration files where appropriate
* Environment variables
* Secure credential storage

YAML should be the primary configuration format.

---

### No Administrator Privileges

The application must:

* Install without Windows Administrator privileges.
* Run without Administrator privileges.
* Never require `sudo` on macOS.
* Never require elevated privileges on Windows.
* Store application configuration in the user's profile directory.
* Store logs/results in the user's profile/application-data directory.
* Avoid writing to protected directories such as:

  * `C:\Program Files`
  * `C:\Windows`
  * `/Applications` when elevated installation is required
  * `/System`
  * `/Library` where elevated permissions are required.

Prefer per-user installation.

### Cross-platform

The application must provide the same functionality on:

* Windows
* macOS

Use a technology stack that supports both platforms well.

Prefer:

**Python backend + PySide6 desktop UI**

### One important enhancement I'd make

For a **truly professional data-validation product**, I would also make the architecture explicitly support a **"control plane vs execution engine"** model:

```text
                 ┌──────────────────────────┐
                 │      Desktop UI          │
                 │  Windows / macOS         │
                 └────────────┬─────────────┘
                              │
                    YAML Configuration
                              │
                 ┌────────────▼─────────────┐
                 │   Validation Orchestrator│
                 └────────────┬─────────────┘
                              │
          ┌───────────────────┼───────────────────┐
          │                   │                   │
    ┌─────▼─────┐       ┌─────▼─────┐       ┌─────▼─────┐
    │   Rules   │       │ Transform │       │ Strategy  │
    │   Engine  │       │   Engine  │       │  Engine   │
    └─────┬─────┘       └─────┬─────┘       └─────┬─────┘
          │                   │                   │
          └───────────────────┼───────────────────┘
                              │
                    Database Adapter Layer
                              │
          ┌──────────┬────────┼────────┬──────────┐
          │          │        │        │          │
       MySQL     PostgreSQL  Oracle  Snowflake   ...
```

That separation will make it much easier later to turn this from a desktop application into an **enterprise data-quality platform with REST APIs, centralized configuration, scheduled execution and CI/CD integration** without rewriting the validation engine.

If you're going to give this prompt to an AI coding agent, I would also recommend asking it to **build the MVP in phases rather than generating the entire codebase in one shot**. That substantially reduces architectural inconsistencies and makes it easier to test the database adapters and validation engine independently.
